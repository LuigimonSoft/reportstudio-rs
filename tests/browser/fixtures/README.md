# PDF reference fixture

`designer-simple-reference.pdf` was generated by the Report Studio TypeScript engine (`layoutOf` and `pdfMeasureText`) and its PDF adapter, using the simple report definition, with the two fictional detail records `Implementation consulting` and `Report development`. The input was normalized with the designer's default element fields. It is a reference for text positions and page dimensions, not a byte-for-byte PDF or cross-platform pixel golden. Recreate it deliberately when the report contract or designer layout changes.

`typography-report.json` is a second normalized input; `designer-typography-reference.pdf` was generated the same way with centered and right-aligned text, bold italic text, underlining, multiline and wrapped text, vertical alignment, and accented WinAnsi characters. The browser test compares extracted positions and widths against this reference, not binary PDF identity.

`table-report.json` and `designer-table-reference.pdf` contain a table created by the designer with a wrapped first row and a second row. Their data is fictional. The browser test compares extracted text positions and widths and checks table borders with a three-level per-channel raster tolerance against the designer PDF.

`number-report.json` and `designer-number-reference.pdf` cover number, currency, percentage and date fields. `footer-report.json` and `designer-footer-reference.pdf` cover single-page page and report footer placement and page counters. Both reference PDFs were generated by the designer using fictional records.

The browser suite also compares `examples/awb/awb-reference.pdf` with the Rust-generated AWB fixture. It checks extracted text and geometry and allows small raster differences (under 0.6% of pixels with channel delta above 16, mean channel delta below 0.5, and maximum delta at most 96). These thresholds cover the fixture and do not imply general visual parity.
